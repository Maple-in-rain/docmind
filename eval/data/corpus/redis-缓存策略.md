# Redis 缓存策略

## Redis 定位

Redis 是内存键值存储，读写延迟在亚毫秒级（单线程处理命令，避免锁与上下文切换开销），常用作缓存、分布式锁、计数器、消息队列。数据存在内存，通过 RDB 快照与 AOF 日志两种机制持久化到磁盘。单线程模型下，慢命令（KEYS、大集合的 O(n) 操作）会阻塞整个服务，生产环境禁用 KEYS 改用 SCAN。

## 缓存读写模式

1. **Cache Aside（旁路缓存）**：读时先查缓存，未命中查数据库并回填缓存；写时直接更新数据库并删除缓存。最常见，逻辑简单，但对一致性只提供最终保证。
2. **Read Through / Write Through**：缓存层代理读写，应用不直接接触数据库。
3. **Write Behind（写回）**：先写缓存，异步批量刷回数据库，写入延迟最低，但宕机有数据丢失窗口。

## 缓存穿透、击穿、雪崩

- **穿透**：查询根本不存在的数据，缓存和数据库都无记录，每次请求都打到数据库。防御：布隆过滤器拦截不存在的 key、把空结果也短时缓存（空值缓存）。
- **击穿**：热点 key 过期瞬间，海量并发请求同时打到数据库。防御：互斥锁重建缓存（只有一个线程查库）、热点 key 逻辑过期 + 异步刷新。
- **雪崩**：大量 key 同一时刻过期，或 Redis 本身宕机，请求全部压向数据库。防御：过期时间加随机抖动、多级缓存、限流降级。

## 过期策略与淘汰策略

过期 key 的删除是惰性删除 + 定期删除结合：访问时发现过期立即删，同时每 100ms 随机抽查一批 key 清理。内存写满时触发**淘汰策略**：`noeviction`（默认，写入报错）、`allkeys-lru`（全量键中淘汰最近最少使用）、`volatile-lru`（只在设了过期时间的键中淘汰）、`allkeys-random` 等。缓存场景通常选 `allkeys-lru`。

## 缓存一致性

先删缓存再更新数据库、先更新数据库再删缓存，两种顺序都有不一致窗口。工业界常用"先更新数据库、再删除缓存"+ 删除失败重试（延迟双删：删两次，第二次延迟几百毫秒，覆盖并发读回填旧值的时间窗）。强一致场景不要依赖缓存，直接读库或使用分布式事务。

## 数据结构选型

- String：计数、分布式锁（SETNX + 过期时间）；
- Hash：对象属性存储，字段可单独更新；
- List：消息队列（LPUSH/BRPOP 阻塞弹出）；
- Set：去重、共同好友（交集运算）；
- ZSet（有序集合）：排行榜（score 排序）、延迟队列（score 存时间戳）。

## 持久化

- **RDB**：定时全量快照，恢复快但两次快照间的数据会丢；
- **AOF**：追加写每一条命令，丢数据少但文件大、恢复慢，`appendfsync always/everysec/no` 权衡性能与安全；
- 生产常用 RDB + AOF 混合：AOF 文件头部是 RDB 快照、后续增量命令。
