# 数据库事务与 ACID

## 事务定义

事务是一组要么全部成功、要么全部失败的操作集合，是数据库保证数据一致性的基本单位。典型场景：转账——A 账户扣款与 B 账户加款必须同时生效或同时撤销，不允许出现"扣了没加"的中间状态。

## ACID 四性质

1. **原子性（Atomicity）**：事务内的操作要么全做要么全不做。由 undo log（回滚日志）实现：执行前先记录旧值，失败时按日志回滚。
2. **一致性（Consistency）**：事务执行前后数据库都处于合法状态（约束、触发器、级联关系不被破坏）。这是事务的目标，由另外三个性质共同保证。
3. **隔离性（Isolation）**：并发事务之间互不干扰。由锁与 MVCC（多版本并发控制）实现。
4. **持久性（Durability）**：事务提交后数据不会因断电丢失。由 redo log（重做日志）实现：先写日志再刷数据页。

## 并发问题

无隔离保护时并发事务会引发四类问题：

- **脏读**：读到其他事务尚未提交的修改（可能被回滚）；
- **不可重复读**：同一事务内两次读取同一行，结果不同（其他事务提交了修改）；
- **幻读**：同一事务内两次范围查询，结果集的行数不同（其他事务插入了新行）；
- **丢失更新**：两个事务基于同一旧值修改，后提交的覆盖先提交的。

## 隔离级别

SQL 标准定义了四个隔离级别，从低到高：

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| 读未提交 READ UNCOMMITTED | 可能 | 可能 | 可能 |
| 读已提交 READ COMMITTED | 否 | 可能 | 可能 |
| 可重复读 REPEATABLE READ | 否 | 否 | 可能 |
| 串行化 SERIALIZABLE | 否 | 否 | 否 |

MySQL InnoDB 默认**可重复读**，且通过间隙锁（gap lock）在多数场景下避免了幻读；PostgreSQL 默认读已提交。隔离级别越高并发性能越差，需要权衡。

## MVCC 原理

MVCC 让读不阻塞写、写不阻塞读：每行记录携带版本信息（事务 ID），读操作读取"自己事务开始时的快照版本"，写操作创建新版本。InnoDB 的实现依赖隐藏列 `DB_TRX_ID`（最近修改事务）、`DB_ROLL_PTR`（指向 undo log 旧版本）和 ReadView（快照）。MVCC 也是"可重复读"实现的基石——同一事务内 ReadView 不变，所以两次读结果一致。

## 锁

- **行锁**：InnoDB 默认，锁住具体行，并发好；需要索引支撑（无索引时行锁退化为表锁，因为无法定位行）。
- **表锁**：MyISAM 默认，写时全表独占，并发差。
- **意向锁**：行锁与表锁的协调机制，加行锁前先在表上标记意向，避免表锁与行锁冲突时逐行检查。

排查死锁：`SHOW ENGINE INNODB STATUS` 查看最近死锁信息；InnoDB 检测到死锁会自动回滚其中一个事务，应用层应做好重试。
