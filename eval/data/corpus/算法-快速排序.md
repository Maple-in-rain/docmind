# 快速排序

## 基本思想

快速排序（Quicksort）由 Tony Hoare 于 1960 年提出，是分治思想的代表算法。每次选取一个基准元素（pivot），把数组划分为两个子区间：左边全部小于等于 pivot，右边全部大于 pivot，然后对两个子区间递归排序。划分完成时 pivot 已经落在最终位置上。

## 分区过程

以 Lomuto 分区为例：维护一个指针 `i`，表示"小于 pivot 区域的末尾"。遍历数组，遇到小于 pivot 的元素就与 `i` 位置交换并把 `i` 右移；遍历结束后把 pivot 换到 `i` 位置。一次分区的时间复杂度是 O(n)。

```python
def quicksort(arr, lo, hi):
    if lo >= hi:
        return
    p = partition(arr, lo, hi)   # 返回 pivot 的最终下标
    quicksort(arr, lo, p - 1)
    quicksort(arr, p + 1, hi)
```

## 时间复杂度

- **最好/平均情况**：每次划分都接近对半，递归深度约 log n，总时间 O(n log n)。
- **最坏情况**：每次 pivot 都取到最大或最小元素（如已排序数组 + 固定取端点），递归深度 n，退化为 O(n²)。

避免最坏情况的常用手段：随机选 pivot、三数取中（首/中/尾取中位数）、对小规模子数组切换到插入排序。C 标准库 `qsort` 与 Python 的 `sorted` 都采用了混合优化（Python 用的是 Timsort，归并排序的变体）。

## 空间复杂度

递归调用栈的深度决定空间开销：平均 O(log n)，最坏 O(n)。快速排序是原地排序（in-place），分区不需要额外数组，这是它相对于归并排序的主要优势——归并排序需要 O(n) 辅助空间，但归并排序是稳定排序且时间复杂度严格 O(n log n)。

## 稳定性

快速排序**不稳定**：分区过程中的交换会打乱相等元素的相对顺序。如果业务要求稳定（如按多个 key 排序），应使用归并排序或 Timsort。

## 与其他排序算法的对比

| 算法 | 平均时间 | 最坏时间 | 空间 | 稳定 |
|------|----------|----------|------|------|
| 快速排序 | O(n log n) | O(n²) | O(log n) | 否 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 是 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 否 |

实际工程中快速排序常因缓存友好性比归并排序更快，这也是它名字的由来——通常情况下的确"快"。
