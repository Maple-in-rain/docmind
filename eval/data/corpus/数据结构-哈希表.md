# 哈希表

## 原理

哈希表（Hash Table）用哈希函数把键映射到数组下标，期望 O(1) 的插入、删除、查找。哈希函数要求：确定性（同键同值）、分布均匀、计算快。Python 的 `dict` 与 `set`、Java 的 `HashMap`、Redis 的核心数据结构都是哈希表的实现。

## 哈希冲突

不同键算出相同下标即为冲突，两个主流解决思路：

1. **链地址法（拉链法）**：每个桶挂一条链表（或红黑树），冲突元素追加到链表上。Java HashMap 在链表长度超过 8 且桶数量足够时把链表转为红黑树，避免攻击者构造大量冲突键导致退化为 O(n)。
2. **开放寻址法**：冲突时按探测序列找下一个空位，如线性探测 `(h + i) % m`。Python dict 用开放寻址 + 伪随机探测，缓存友好性更好，但删除需要"墓碑标记"（直接置空会切断探测链）。

## 装载因子与扩容

装载因子 α = 元素数量 / 桶数量。α 过大会导致冲突加剧、性能退化；α 过小则浪费内存。Python dict 在 α 超过 2/3 时扩容（新容量约为原来的 2 倍），扩容时全部键重新哈希迁移，单次扩容 O(n)，但摊还分析后插入仍是 O(1)。攻击场景：不断触发扩容可造成性能抖动，即"哈希洪水攻击"，Python 3 用随机化哈希种子（每次进程启动随机生成）使攻击者难以预测下标。

## 哈希函数的要求

- 相同对象必须返回相同哈希值（`hash(a) == hash(b)` 若 `a == b`）；
- 相等的对象哈希必须相同，反之不成立——哈希相同可能只是冲突；
- 可变对象（如 list）不能作为 dict 的键，因为内容变化后哈希值会变，导致元素"丢失"。`tuple` 不可变所以可以作为键，但 tuple 内含 list 同样不行。

## 时间复杂度与陷阱

- 平均 O(1)，最坏 O(n)（全部键冲突成一条链）；
- 遍历 dict 的顺序是插入序（Python 3.7 起保证），不是键的大小序；
- 若需要有序遍历，用 `collections.OrderedDict`（语义明确）或排序后的列表；需要按值排序用 `sorted(d.items(), key=lambda kv: kv[1])`。

## 典型应用

两数之和（一次遍历 + 查表）、缓存（LRU 用哈希表 + 双向链表）、去重（set）、词频统计（Counter，dict 的子类）、路由表与符号表。
