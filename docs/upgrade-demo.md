# DocMind 升级演示与验证

## 已实现范围

- 普通 RAG：多轮问题补全，单轮跳过，5 秒超时或不合法输出回退原问题，可通过 `QUERY_REWRITE_ENABLED=false` 关闭。
- 证据展示：来源卡片展示模型实际收到的截断后片段，保留文档、片段编号。无检索结果时直接说明资料不足。
- 方案分析：单 Agent，模型选择工具并依据结果继续查找；请求内维护任务维度、完成项和证据缺口。独立 `/api/agent` SSE 入口。
- 工具：文档分页列表、混合检索、相邻片段读取、请求内任务更新。所有参数校验；禁止调用未登记工具。
- 执行上限：6 次工具调用、8 次模型回复、90 秒任务预算；相同参数的重复调用跳过但仍消耗调用预算。刚好用完工具预算后，允许在剩余模型轮数及时间内生成最终报告，不再执行工具。
- 前端：普通问答/方案分析模式、计划与查找记录、终止状态、报告复制。报告以纯文本 Markdown 展示，沿用现有页面风格。

## 启动与演示

正常启动沿用 README；接口使用服务器已有 Provider 配置。工具调用协议参考 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/tool_calls/)。模型名称仍由 `DEEPSEEK_MODEL` 配置；如供应商已调整模型别名，请使用账户当前支持的工具调用模型。

仅检查执行流程时，可在项目目录启动独立的 mock 实例，避免读写原知识库：

```powershell
$env:LLM_PROVIDER='mock'
$env:EMBEDDING_PROVIDER='mock'
$env:RERANK_PROVIDER='mock'
$env:DATA_DIR="$PWD/.demo-data"
python -m uvicorn app.main:app --host 127.0.0.1 --port 8011
```

环境变量只影响当前终端；关闭后在新终端使用真实配置。mock 的向量和回复不具有语义能力，报告明确标注 mock，不能用来声称分析效果。不要在同一数据目录混用 mock 和真实向量。

将 `scripts/sample_data/comparison/` 的三份 Markdown 上传到该实例。它们是简化演示文档，不是经过生产验证的技术建议。

演示顺序：

1. 普通问答：“方案乙的更新顺序是什么？”随后追问“等待多久？”；真实模型下对照关闭问题补全后的检索结果。
2. 普通问答：“方案丙保证多少毫秒内完成缓存失效？”检查是否明确文档没有该数据。
3. 切换方案分析：“对比三份方案的一致性、恢复方式和实现运维成本，列出适用条件与待确认问题。”
4. 展开记录，说明计划、搜索、上下文读取和任务更新；核对报告引用与原文，复制 Markdown。
5. 展示一个资料不足或执行停止案例，说明预算和模型能力边界。

## 同题记录

`eval/data/upgrade_cases.json` 包含 20 条初始案例，覆盖单轮、追问、换话题、无答案和方案对比。全部 `reviewed=false`；先人工审阅再用于效果结论。出处文本存在性检查不能代替标注审阅。

```powershell
python scripts/compare_modes.py --dry-run
python scripts/compare_modes.py --base http://127.0.0.1:8011 --limit 2
```

脚本将两种模式的回答、来源、工具事件、耗时和人工评分空栏追加写入 `eval/results/upgrade_comparison.jsonl`。记录脚本不上传文档、不修改知识库；默认执行全部案例会使用服务器配置的 API 额度。每次先用 `--limit` 做小范围检查。

追问案例使用预设历史，Agent 收到等价的文本上下文；普通聊天收到消息数组。比较记录应注明该输入形式差异。对比场景使用相同语料、模型和检索配置，不预设 Agent 一定更好。建议比较：证据是否覆盖问题、结论是否受来源支持、缺失信息是否如实说明、耗时与模型调用次数。

## 可以讲清楚的实现选择

- 固定 RAG 适合普通问题，Agent 在需要多次查找与补充上下文的任务中提供另一条路径。
- 模型生成工具调用，服务端执行并回传 `tool_call_id`；模型不能自行执行代码。
- 状态保留在一次请求内；每次请求创建独立工具对象，避免不同任务证据串用。
- 搜索结果与邻接片段共用证据编号，重复读取同一片段不重复编号。每片段最多 1200 字符，任务证据总正文最多 12000 字符。
- 编号检查能阻止引用不存在的来源，不能证明文字结论正确。任务清单的完成状态也是模型报告，需要结合工具记录核对。

## 当前限制

- 尚未以真实模型完成这组案例的人工语义验收，不能填写成功率或提升比例。
- 追问补全也可能错误引入上下文；异常回退只能保护运行可用性，不能保证改写正确。
- 搜索在全库进行；文档较多时指定某份方案的证据可能需要按编号读取。当前上下文工具每次最多读三个片段。
- Agent 报告在分析完成后输出，工具进度实时推送；当前不是报告逐 token 流式生成。
- 工具超时或客户端断开会取消等待和后续循环，并通过取消标记阻止后续检索阶段、重排重试与证据写入。但 `to_thread` 中已发出的同步 HTTP 请求无法强制终止，可能持续到自身超时；没有将这个限制包装为硬实时取消。
- 当前 Agent 只分析已上传资料，不联网搜索，不读任意文件，不修改文档，不提供长期记忆。
- 原有入库跨 SQLite/Chroma 的失败清理属于后续独立修复，本次未宣称解决。
